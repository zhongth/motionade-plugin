# Motionade native authoring adapter

Technical interface only. The server's own answers (its capability sections, each kind's contract, its refusals) are the authority: where they differ from this page, follow them.

## Source of truth and discovery

`ProjectDocument` contains scenes, objects, and MotionBlocks. `MotionBlock.program` is the authored MotionProgram. Human editing, external agents, and the internal co-designer use validated `ProjectOperation`s. Create native editable objects and motion; never write project repository files directly or use Remotion JSX as authored state.

1. Call `listCapabilities({})` first. Its `sections.onDemand` index names supported discovery sections. Read section `model` once before you author, and look each need up in section `needs` ([the skill's start](../SKILL.md#start-here) gives the order).
2. Read `listCapabilities({section:"actions"})` for current action ids, facets, channels, targets, and composition. `section:"operations"` lists every operation kind with its required and optional fields. Fetch other sections only when needed.
3. Read `getProject({projectId})` and `getSceneAuthoringContext({projectId,sceneId})` before editing. The latter supplies project default segment timing and CAS fingerprints.
4. `applyOperations` accepts an array of operation records; MCP `tools/list` does not carry each operation's nested schema. Before you write a kind, read `listCapabilities({kinds:["<kind>", …]})` (up to 20 names): each kind's exact input as JSON Schema, the rules the schema cannot say (`conditions`) and field units, worked examples, and where to read when it is refused or needs project facts. A placeholder in an example names the read that supplies its value, such as `<getSceneAuthoringContext: cas.textSnapshots[objectId=…].snapshotFingerprint>`. `section:"examples"` gives worked `addObject` (Text) and `materializeActionFacets` payloads. A refused operation is named by `failedIndex` and `kind`; `issues` gives each field it is about (`path`, the value `received`, what was `expected`), `fix` what to send instead when the message does not already say it, and `read` the one call that answers the rest: the kind's contract (`listCapabilities({"kinds":["<kind>"]})`), the kind list, the project's or the Scene's ids (`getProject`), its fingerprints (`getSceneAuthoringContext`, `inspectPathRegions`), the font families (`fontFaces`) or the brushes (`listBrushLibrary`).
5. Leave out the values with no creative meaning, the ones the rest of the operation or the project decides: the stage fills them, and its answer lists each filled value once under `filled`, with its field path and the indices of the operations it went into. A value you send is kept or refused, never overwritten: kept when it matches, refused with the expected value named when it does not, and kept as sent when it is authored state (a baseline, controls, a name). The one exception is an auto-sized Text's measured box, which the stage replaces and reports in `filled` marked `measured`.

## Live transaction and checkpoints

The stage/inspect/accept transaction:

```text
createProject → getProject + getSceneAuthoringContext → save workspace checkpoint
→ applyOperations → inspect candidate + warnings + overwroteUserEdits
→ renderFrame / renderMotionStrip / previewRange / getPacingReport with proposal.stageId → acceptOperations
→ getProject + getSceneAuthoringContext → save readback → openEditor
```

`createProject({name,format:{width,height,fps}})` saves a blank native project with one scene. Read its scene id; do not assume an id from another project. `applyOperations({projectId,operations})` validates and stages atomically, returning `proposal` (`stageId`, `projectId`, `baseRevision`, `proposalDigest`), a `candidate` outline (its scenes with ids, durations and object counts), `warnings`, `overwroteUserEdits`, the pacing and morph reports, and `expiresAt`. Warnings that differ only in their quoted ids or names come once: the `message` marks each with `"…"`, `count` says how many, and `each` lists every one's `quoted` values. An answer that would pass the 48 KiB tool result limit keeps the first entries of each list: `omitted` counts what each list left out (a warning group that lists only some of its members says how many it left out in `eachOmitted`) and carries a `download` of the whole answer. Its link expires in about 5 minutes and cannot be renewed, so run its `save` line at once. `getProject({projectId})` returns an `outline` (revision, byte size, scenes with ids, durations and object counts) and the whole document as `document` while it fits a tool result; a larger document comes as `download`, a five-minute link to gzip JSON: run its `save` command from the task workspace, never the user's repository, and read the `<projectId>.r<revision>.json` it writes there (`.stage-<stageId>.json` for a candidate). `getProject({projectId,stageId})` does the same for the staged candidate. There is no separate `validateProject` MCP tool. Failure (`ok:false`) means no candidate was accepted.

Save the before document, authored operations, complete stage response, verification notes, and accepted readback to a task workspace. These checkpoints are separate from Studio History. Keep prior checkpoints intact. Accept with the returned `proposal.stageId` and `proposal.proposalDigest`: `acceptOperations({stageId,proposalDigest})`. Copy both values exactly; the digest names the exact staged proposal. A Stage saves once: repeating the same accept (for example after a lost answer) returns the same receipt, `{projectId, revision, warnings, sceneNotes}` (`sceneNotes` where the server keeps Scene notes). It expires after 30 minutes and checks the base revision. A replacing Stage, expiry, an intervening edit to what its `scope` covers, or a local server restart requires a fresh read and restage. `discardOperations({stageId,proposalDigest})` consumes an abandoned stage without changing saved state.

Within the authorized creation/editing task, accept a verified change automatically. Honor explicit preview/review requests. Resolve any unrequested overwrite reported in `overwroteUserEdits` before acceptance. Re-read CAS fingerprints after each accept; use them for the operations that require them. Do not infer a repository revision from timestamps: the proposal carries `baseRevision`.

Each stage answer's `scope` says what the Stage settles against, and a newer Stage replaces only one of the same scope. A Stage that changes only one Scene (`{kind:"scene",sceneId}`) lands on the latest project while that Scene is unchanged, so authors of different Scenes stage and accept side by side; any other Stage (`{kind:"project",because}`, naming what made it so, such as `fontManifest` for a new font) needs the whole project unchanged, so any accept or saved edit makes it stale: accept or discard your last one before another agent or the person takes the project over.

When several agents share a film, `setSceneNote({projectId,sceneId,owner,status})` says who works on a Scene and where it stands (`draft`, `done` or `reviewed`); `getProject` shows every Scene's note, and stage and accept answers the notes of the Scenes they change, with `changedSinceReview` once an accept, or the person's edit in Studio, changes a reviewed Scene. The note reports and never locks: a reviewer sets `reviewed`, or `draft` to send a Scene back, and an author that finds its Scene back at `draft` reworks it.

## Scene structure and cross-scene continuity

The blank Scene returned by `createProject` is a transport starting point. Implement the chosen design's Scene map before filling the whole film with timed objects. A native Scene is an editable sequence container; the editor's page/deck analogy does not prescribe presentation composition.

Read the contracts of `addScene`, `duplicateScene`, `reorderScene`, `updateSceneDuration`, and `setTransition` before use. Inspect each boundary after authoring it: frames on both sides, and a frame run across it.

Objects and their parents are scoped to a Scene. Do not invent cross-Scene parent links or assume one object persists automatically into the next. For matched instances, use corresponding appearance/pose and an explicit note of any manually coordinated edits. Object ids are Scene-scoped; a `sharedElement` transition requires the same objectId in both Scenes. Verify rendered scale, crop, visibility, and motion phase on both sides. Use an actual supported transition when the design calls for one; a clean cut needs no effect.

An Action cannot outlive its Scene, so a move that continues through a cut is two Actions on matched objects, one per side, cut from one planned curve. Plan the move on film frames `g0…g1` and find the outgoing Scene's last frame `gc` from the timeline layout. The outgoing Action runs `g0…gc` and ends at the curve's value at `gc`. The incoming Action starts at its Scene's frame 0 with the value at `gc+1` and runs to `g1`. Linear motion then continues exactly. For eased motion, author the crossing segment as a `cubicBezier` so each side can carry its exact piece. Take the piece over time fractions `[0, (gc−g0)/(g1−g0)]` for one side and `[(gc+1−g0)/(g1−g0), 1]` for the other. Find the Bézier parameters at those x values, split the curve there (de Casteljau), and rescale each piece to the unit box. A named preset has no exact split. Text already partly typed at the cut follows the same pattern: a static prefix plus a typed remainder. Verify on `renderFrame` at `gc−1`, `gc` and incoming frames 0 and 1: the pose and the per-frame travel should run on without a jump.

Keep local keys in their Scene's clock and derive project offsets from the current timeline layout. Overlap transitions can change offsets and total duration; a simple duration sum may be wrong. Preserve continuous project-level music when appropriate, and recheck cue alignment after changing a Scene duration or transition.

## Coordinates, time, and native text

- Scene format dimensions and object x/y/width/height use pixels. A root object's untransformed x/y is its upper-left position; a parented object's position is local to its parent. Scale is unitless; rotation/skew use degrees. Object origin defaults to normalized `(0.5,0.5)`.
- Scene frames and MotionBlock starts are scene-relative integers. A range is half-open: `[startFrame,startFrame+durationFrames)`. A key's `frame` is local to its Action, with `0 <= frame < durationFrames`. A 60-frame Action may end at key frame 59. Seconds = frames / project fps.
- `previewRange`, `renderFrame`, and `openEditor` frame arguments are scene-relative. Use `screenBounds` when a camera transforms geometry, otherwise `renderedBounds`; raw x/y does not account for all painter transforms or text sizing.
- `compose:"replace"` pairs with `keyframeOperation:"set"`; `add` pairs with `offset`; `multiply` pairs with `scale`. The raw sample becomes, respectively, `value`, `value - baseValue`, or `value / baseValue` before composition. A scale baseline must be nonzero. Coupled component ids must match across components, operations, baseValue, and all key values.
- Use `style.primaryFill:{kind:"solid",color:"#rrggbb"}` for a solid native fill. Old `fill`, `color`, and `fillGradient` object-style fields are retired. Change an existing solid or gradient fill with `setObjectPrimaryFill {sceneId,objectId,fill}` and a Scene background with `setSceneBackgroundFill`; `updateObjectStyle` refuses `primaryFill`. Shader fills use `addShader`.
- Native text uses `content:{kind:"text",design:{text:"Text"}}`; `styleRuns`, `segments` and `segments.manual` left out are none. For word or letter segments, `segments.active.items` may list one `{id}` per word or letter; the stage fills each range and text, and refuses a count that does not match the text. Typography is in `style.fontFamily/fontSize/fontWeight`. Query `listCapabilities().fonts`; `Geist` is the current default. Bundled and curated Google families are listed there; staging fetches a listed family and persists it as a project asset. A family with `variable` in `listCapabilities({"section":"fontFaces"})` renders any weight in its range; other families bind the nearest of 400/500/600/700, so 800 and 900 render as the 700 face there. Measure the result when a heavier face matters.
- A glyph that neither the chosen face nor the CJK/emoji fallbacks cover paints as an empty box. The stage warns `missing_glyphs` (or `missing_glyphs_unchecked`, naming the fonts, when a font could not load while staging and the check did not run), and `renderFrame` and `previewRange` still render and name the object and characters in `warnings` (`missingGlyphs`); Studio export names them and asks before exporting the boxes. Draw such symbols (✦, ↻, arrows outside the font) as native shapes.
- External staging prepares native font bindings, for a new Text and for a font change on an existing one (`updateObjectStyle` family, weight or style, a style run); do not fabricate manifest hashes or asset integrity. Inspect missing-font/render failures. Text defaults to `auto-width`; explicit `auto-height` fixes width and wraps, while `fixed` clips to its rectangle. Native text remains editable. Measure auto-width text through the production layout (a throwaway `previewRange`/`renderFrame` with the text) before placing neighbors or centering; guessed widths drift. The stage fits `auto-width`/`auto-height` text to that measured extent, anchored by `textAlign`/`verticalAlign`, and reports the box in `filled`, marked `measured`. Leave the measured sides out (both for `auto-width`, the height for `auto-height`, which keeps its width as the wrap width): `x`/`y` then place the text by its alignment, as clicking does in Studio. A supplied box is only a starting point.

## Editable actions and timing

Use `materializeActionFacets` with `action.mode:"create"` for normal editable channel animation. Read the action catalog first. A create carries the whole key list, each key before the last with its own `outgoingTiming` (omitted means the project default). `addMotionBlock` is the expression/program route and rejects ordinary fully editable catalog Actions.

**Object lifetime.** An object paints only inside its lifetime, and the engine derives it from the Actions' `stage`: the earliest object-addressed `stage:"in"` start is the lifetime start, and the latest `stage:"out"` end is its exclusive end. Object-addressed includes Actions on one text segment or a text-segment group, so a word cascade counts. An endpoint with no In or Out Action comes from `object.range`, then the Scene. A parent's lifetime also bounds its descendants.

**Give every entrance and exit its stage.** For anything that appears after its Scene starts, give its first entrance Action `stage:"in"`: a fade, a rise, a scale-in or a word cascade alike. Give an exit `stage:"out"`. The object is then hidden before its entrance starts and after its exit ends, so it never sits at rest before it enters. Use `stage:"custom"` for changes inside the lifetime (a pulse, a move to a new place, a colour change) and for a single-property program with several phases. Use `object.range` only for an object with no entrance or exit animation (it cuts in or out), or one whose lifetime must differ from its Actions, such as one visible before its first Action starts; its Actions then stay `custom`. Every catalog Action defaults to `custom`, so set `in` and `out` yourself. `persistence.post:"hold"` keeps a property's last value; it does not extend the lifetime. Check the frames just before and after each boundary with `previewRange`.

Range Actions require `persistence.pre:"release"`: before an Action starts, the property shows its Design base value. When a property must hold a non-base value until a cue, start the Action at the object's first visible frame and hold the first value until the cue: `(0,v0,hold) → (cue,v0,curve) → (cue+d,v1)`. Two range Actions writing the same property with `replace` do not refuse; while they overlap, the later one in document order wins. Phases of one property inside the lifetime (a hold, a change, a change back) belong in one `custom` Action; an entrance and an exit are two Actions, `in` and `out`. A held In keeps writing after it ends (`persistence.post:"hold"`), so on the same `replace` property put the In before the Out in document order, or end the In at the base with `post:"release"`; otherwise the held In wins and the exit plays invisibly. A Resize key must keep width and height at `base + delta ≥ 0`, where `base` is the Design box or, when that refuses the key, the Design box plus what earlier Actions that have ended and hold leave on width and height at the key's frame (normally earlier Resizes; one still running does not count). So a later shrink after an earlier grow is accepted. Only the keys you write are checked, and a refusal names a key value that would pass. An Action spans at least two frames; a single key with `persistence.post:"hold"` changes a value once, and a value that never changes belongs on the object's base.

An Action create needs what only you decide: `catalogId`; `blockMetadata` with `id`, `target`, `stage` and `timing:{startFrame,durationFrames}`; and per facet a primitive with `id`, `kind` (`property.write`, or `property.writeGroup` for a coupled facet such as move or scale), `persistence:{post}` (`hold` keeps the last value after the Action ends, `release` returns to the Design value) and `value.keys`. The stage fills the rest from the catalog row and the project: the `facetId` of a one-facet row, the primitive's `target`, `property` or `components`, `compose`, `persistence.pre`, `value.kind`, `keyframeOperation(s)` and `baseValue` (0 for add tracks, 1 for multiply tracks, the target's Design value for replace tracks), and the block's `role`, `name` (the catalog label), `timing.kind`, `controls:[]` and `editability:"full"`; a camera row's `target`; a cascade's `segmentSchedule.unit`, `baseOffsetFrames` and `timing.durationFrames`. A `baseValue`, `name` or `controls` you send is kept as sent. `editability` may also be `parametric`. `transform-only` and `locked` are refused, because a person must be able to edit an agent's Action. A coupled facet's key values are keyed by channel (`{x, y}`). Omit Action `source`, `editState`, `ownedResource`, `programMetadata`, and keyframe `baseValueProvenance`; the boundary supplies these. Mint unique block, primitive and key ids. `insertMotionKey`, `updateMotionKey`, `removeMotionKey`, `updateMotionSegmentTiming` and each `updateMotionKeyBatch` edit may leave out `valueTrack` when the primitive has one keyframe track. After materialization, read actual primitive ids from the candidate/readback.

Canonical Actions can expose native key, transform, timing, and easing editors with `controls:[]`; that array declares no custom MotionBlock controls. Describe the editing surface actually verified. Scale key values can be edited in the selected-key panel on every target, and through Design transform controls at the selected frame. Test the relevant selection/ownership and Undo path before promising a particular manual adjustment.

For bootstrap boundaries, copy the returned `defaultSegmentTiming.continuous` or `.discrete` verbatim. Current defaults are:

```json
{"continuous":{"kind":"easing","preset":"easeInOutQuad"},"discrete":{"kind":"hold"}}
```

An outgoing segment timing lives on its **left key**. The last key needs no outgoing boundary. The creation/default contract does not prohibit later deliberate curve editing: use `updateMotionSegmentTiming` on an existing left key. Put such a boundary in the create itself, for example the `(0,v0,hold)` lead-in above as `outgoingTiming:{kind:"hold"}`.

Current timing forms:

| Form | Exact shape / bounds |
| --- | --- |
| Linear | `{kind:"linear"}` |
| Hold | `{kind:"hold"}` |
| Named curve | `{kind:"easing",preset:"easeOutCubic"}` using a supported name |
| Cubic Bézier | `{kind:"cubicBezier",x1,y1,x2,y2}`; x1/x2 in 0..1, y1/y2 finite |
| Spring | `{kind:"spring",bounciness,speed,velocity?}`; bounciness/speed in 0..1, velocity finite; numeric tracks |
| Timing style | `{kind:"timingStyle",styleId}` referring to an existing compatible project timing style |

The exact easing names currently advertised are `linear`, `stepEnd`, and `easeIn*`, `easeOut*`, `easeInOut*` for each suffix: `Sine`, `Quad`, `Cubic`, `Quart`, `Quint`, `Expo`, `Circ`, `Back`, `Elastic`, `Bounce`. Segment timing uses explicit `linear` and `hold` arms; it rejects `linear`/`stepEnd` inside the `easing` arm. `continuation` is a system-owned timing form; never author it.

## Local key repair

Address the existing block, primitive, value track, and key. `updateMotionKey` takes the complete key and requires `key.id === keyId`; preserve its existing outgoing timing when changing only frame/value. For a coupled Move:

```js
{
  kind: "updateMotionKey", sceneId, motionBlockId, primitiveId,
  valueTrack: { primitiveKind: "property.writeGroup", track: "value" },
  keyId: key.id,
  key: { ...key, value: { ...key.value, x: 420 } }
}
```

For a scalar property use `primitiveKind:"property.write"`. `insertMotionKey` omits `keyId`; `removeMotionKey` omits `key`. `updateMotionKeyBatch` performs atomic multi-key edits. `updateMotionSegmentTiming` uses the same address plus `keyId` and `timing`. `retimeMotionAction` moves or stretches the existing Action; `updateMotionBlockTiming` changes its timing. Prefer these local edits to replacing primitives or recreating the project. They preserve the editor's visible native keys and identities.

## Media from your own files

A photograph, a generated background, a texture, footage, or music enters as a file; UI and logos stay native constructions.

1. Read the file's byte size and `shasum -a 256`.
2. Call `createMediaUpload` with its `path`, `mimeType` (images: PNG, JPEG, or WebP, up to 20 MB; video: MP4, MOV, or WebM; audio: MP3, M4A, AAC, WAV, OGG, or FLAC), `size`, and `sha256`.
3. `ready` returns an `asset`. `upload` returns a `curl`: run it exactly, then call `createMediaUpload` again with the returned `id` until `ready`. `processing` means call again: images take seconds, video can take minutes. `failed` means fix the file and use a new id.
4. Stage `addAsset` with that `asset` unchanged — the server owns `mediaMetadata` — and an image or video object whose `content.assetId` is its id (audio: `addAudioClip`). Size the object from `mediaMetadata`; `style.objectFit: "cover"` fills a full-frame background.
5. `renderFrame` with the `stageId` shows an image's real pixels before you accept.

The file joins the user's media library, where Studio can reuse it. Media enters a project only this way: a remote address or another account's file is refused at stage.

## Shaders you write

A Shader paints an object's fill, a Scene background, an Effect on an object, what shows behind an object, or a post effect over the whole Scene (`addShader`); section `visualCatalog` lists the ready-made looks. For a look of your own, write the SkSL yourself and decide which of its values a person can retune and keyframe in Studio. Each of those is a Property: declare it with its control (a slider, a colour, a toggle, a point, …) and read it in the source as a `p_` uniform. Every other value is a constant in the source, which Studio cannot change: it has no SkSL editor. Time is a Property too. There is no time uniform: declare a number Property for it and name it in `shader.phase`, and the server drives it with a linear ramp whose speed and offset a person can retune. Check each version with `compileShader` before `addShader`; it compiles and probes the shader as the stage will and answers with line-numbered errors. Retune a placed Shader's values with `updateShaderValues`. Key one over time with `keyShaderProperty` at Scene frames: the keys land in the placement's Effect block, where a person drags them, and the stage answer's `shaderKeyReport` gives each key's block frame, the frame `updateMotionKey` and the other key operations take. Section `shaderAuthoring` holds the whole contract: scopes, inputs, reserved uniforms, limits and traps.

## Large batches by file

A batch your own code wrote, such as a whole Scene or many keys, goes by file so its bytes never pass through the conversation. Small edits stay inline.

1. Write the operations array to a file in the task workspace, exactly as you would pass it in `operations`. Read its byte size and `shasum -a 256`, or run `motionade send ops.json`, which checks the file is an array of operations and prints its `path`, `size` and `sha256`.
2. Call `createOperationsUpload` with its `path`, `size` (up to 8 MiB) and `sha256`. Run the returned `curl` exactly, or `motionade send ops.json --to <upload.url>`.
3. Pass the returned `ref` as `operationsRef` in place of `operations`: to `applyOperations` to stage it, or to `renderFrame`, `renderMotionStrip`, `previewRange` or `getPacingReport` for a throwaway fold. The answer is the same as for inline operations.

The batch budgets under "Preview, playback, and export limits" still apply, so a film still goes in several stage and accept rounds. An uploaded batch is kept for an hour, and a restage of the same batch can reuse its `ref` until then. A changed file needs a new ticket: the server refuses bytes that do not match the `sha256` the ticket named.

Renders can come back the same way. With `deliver: "link"`, `renderFrame` and `renderMotionStrip` answer with `download` instead of the image: run its `save` command, or `motionade fetch <url>`, to fetch the PNG into the current directory, for a script to compare or assemble. The link is valid for 15 minutes. Look at an image yourself when judging it; use links when a script handles many frames.

The plugin's `motionade` command does these mechanics; every step above also works without it. `motionade fetch <link>` saves a project download too, unpacked. `motionade compare <frame.png> <reference>` measures a frame against a reference image with ffmpeg: SSIM, PSNR, the share of changed pixels, a side-by-side image and a difference image. It says when ffmpeg is missing. Exit code 4 means a link has expired, was used, or its file was cleared: ask the tool for a new one. Exit code 5 means the link could not be reached: allow this command network access (in Codex, the sandbox has none by default) or run the ticket's `curl` line. Exit code 6 means storage is busy or failing: wait a minute and run again. Check with `command -v motionade` first: when it prints nothing, run `node <plugin folder>/bin/motionade` in its place, where the plugin folder is the one that holds `skills/motion-design/SKILL.md`.

## Preview, playback, and export limits

`previewRange` is numeric sampled geometry; pass `objectIds` on busy scenes, since a result above 48 KB is refused with how to narrow it. `renderFrame` is a PNG from the production painter, with missing-assets/font diagnostics. Pass `stageId` to inspect the staged candidate; omitting it inspects saved state. Neither tool proves continuous playback, audio synchronization, manual editing usability, or successful video export.

After staging motion that eases, arcs or hands off, call `renderMotionStrip` with the `stageId` and mode `onionSkin` before you accept, passing `objectIds` for the objects that move: the ghosts show the spacing (bunched where it eases, even where it is linear), the path's shape, and any retraced exit or collision in one image. Use `contactSheet` to check poses and cuts across a range, with frames labelled. The strip shows paths and spacing, not timing; use `getPacingReport` for holds and rhythm.

Headless `renderFrame` paints raster images (PNG, JPEG, WebP, GIF) with their real pixels. A library video paints its poster, its first frame rather than the frame at that time, and `warnings` notes it as `video-poster`. An SVG or AVIF image, media still processing, and a video outside the library paint as flat grey placeholders at the object's opacity; each appears in `missingAssets` with its reason in `warnings`. Such a placeholder is expected, not a construction failure: judge placement and size from it; the real pixels show in Studio. `previewRange` reports no assets.

One `applyOperations` batch may contain at most 100,000 JSON nodes of the raw authored operations (arrays and record entries, counted before expansion); a larger batch fails with `invalid_project_operation`. Split dense construction into sequential stage/accept batches, and review every batch rather than only the last. A large stage can outlast an MCP client's default request timeout; raise the client timeout rather than retrying blindly. A stage stops folding after 30 s with `stage_budget_exceeded` and names a batch size to split into, so a hosted stage answers inside its 60 s request limit. Each operation re-checks its whole Scene: on a Scene of 770 objects that measured about 0.15 s per operation locally, so 100 operations there take about 15 s before the stage measures the changed Scenes and records the candidate. `stale_revision` at accept means what the Stage's `scope` covers really changed after staging, by a person's edit or another agent's accept, and names the Scene when it is one: re-read and restage. `scene_merge_invalid` means the Scene is unchanged but a change elsewhere breaks a rule with it, which the message names. A Studio save that changed nothing does not fail Accept, and the stage fits agent text, so an open Studio window's refit on mount does not cause it. `getSceneAuthoringContext` takes an optional `objectIds`, and refuses a result above 48 KiB with `result_too_large`; on busy scenes, pass `objectIds` as you would to `previewRange`.

The film at speed and with its sound is the person's to watch in Studio. Export only when they ask for a file or for delivery: see "Export and deliver".

## Export and deliver

The film renders on the user's machine through Studio's own export: the painter the preview uses, then the browser's encoders (CanvasKit → WebCodecs → MP4). Nothing renders it on a server.

Chrome cannot start inside a coding agent's shell sandbox (exit 14 with Chrome installed), and the driver's one-time install, playwright-core into `~/.motionade/runtime`, needs network and writes outside the work folder. So each runs outside the sandbox with the person's approval: name the exact command you will run when you ask, then run that command there.

1. Call `createExportLink` with the `projectId` and a `quality`: "draft" (720p at most, for review) or "delivery" (the project's own size, high quality). Pass a `sceneId` for one Scene as it plays in the film, transitions and sound included. The answer has the `url`, the `revision` it reads, the frames it holds (`window`) and the file's `output` size. The link reads only that revision. Open it within 30 minutes; an export opened in time may run 15 minutes past that. After any accept, ask for a new one.
2. Run `command -v motionade` on its own; it needs no approval. If it prints a path, export with `motionade export '<url>' --out <new file>.mp4`; if it prints nothing, with `node <plugin folder>/bin/motionade export …`. Either way, run the export as a command of its own and ask approval for that exact command: with `;`, `&&`, `|`, `echo` or `$(…)` around it, the whole command stays in the sandbox, approved or not. It opens the link in the user's Chrome or Edge, headless and with the browser's sandbox on, saves the MP4 (never over an existing file), and prints a receipt as JSON; progress goes to stderr. `--browser chrome`, `edge` or `chromium` (Playwright's own) picks the browser; a path is taken only when it is Chrome's or Edge's own executable where it installs, and anything else exits 1: `--browser` names a browser, never a program. It needs playwright-core 1.60 or later, which downloads no browser: when it is missing or older, it exits 15 and prints the one install command.
3. Read the receipt. `checks` holds only the checks that ran, and `status` "passed" means each of them passed. With ffmpeg installed they cover the file being the one the page made, every image, medium and font loading (`everythingLoaded` names any that did not), the project unchanged while it exported, the picture's size and frame count and a clean decode, and the sound covering the picture, starting where the mix starts, and keeping the mix's loudness. Without ffmpeg only the first three run: `status` is then "passed with skipped checks", and `skipped` names the rest. Say which checks ran when you report. `warnings` names sound that ends before the picture, Effects exported as a fallback, and requests from another server the film does not use that were blocked or failed, such as a script a preview deploy injects; those never fail the receipt. Read `review.notesKept` first: when true, `review.unreviewed` lists the exported Scenes not marked reviewed (no note, another status, or changed since review), and a warning names them; it never fails the receipt either. `notesKept: false` means the server keeps no Scene notes, not that every Scene is reviewed. With `--play` the script also plays the saved file in the browser at normal speed and checks that it plays to its end; it takes the film's length, and `notRun` says when it was not asked for.

Every run prints JSON: the receipt, or `{ok: false, error: {code, message}}`. Exit codes: 0 passed; 4 the link expired: ask for a new one; 17 the link was refused (the project changed, a Scene is missing, the project carries flags); 18 the export is blocked (characters no font covers, a font that cannot load, media not ready, a browser without the encoders); 19 the file was saved but a check failed; 14 Chrome or Edge could not start (not installed, or blocked by a shell sandbox, as above); 20 timed out; 21 the link is not https or local; 22 the link's server did not serve the export page; 23 the browser crashed; 24 the file did not download; 25 a file appeared at `--out` meanwhile (the film is kept beside it, named in the error); 1 usage; 2 any other failure. When the command cannot run, the same link opens in the user's Chrome or Edge, where the page renders the film and downloads the file: ask the person to open it.

A draft the person asked for is the real film with its sound: take frame sheets, the frames around cuts, and the sound from it with ffmpeg, and compare it with a reference. Export needs H.264, and AAC for sound. Google Chrome encodes both. Playwright's bundled Chromium encodes neither, and Edge on Linux has no AAC, so its exports are silent; the receipt says so. Claim an export only from a file with its receipt, never from a diagnostic PNG or an external renderer.

## Engine notes

These are engine behaviours, not design rules.

- Omit `object.editState` on `addObject` and other document carriers; the boundary stamps it. A supplied value is dropped with a warning and will be refused in a later release. Facet primitives, key ids, and `blockMetadata.id` still take caller-minted ids.
- A Frame's `opacity` fades the Frame and its whole subtree as one layer. `backgroundOpacity`, with its own Action, fades only the Frame's fill and stroke. Transforms cascade through Frames, so animate an owner rig rather than every leaf. An Effect or a `layerBlur` on a Frame filters the Frame's own fill and stroke and its whole subtree as one image, so put an Effect on the leaf you mean; the catalog `shadow` Action does not target Frames.
- Colour keys and color interpolation run in HSLA (advertised as `colorInterpolation.colorSpace:"hsla"`); no other colour space is available. A settle from a saturated colour to black or white passes through desaturated, shifted hues. Choose an endpoint at the same hue (a near-black of that hue), or add intermediate keys measured from the intended in-between colour.
- `addTextCaret` follows the letter windows its Action's `segmentSchedule` resolves to, overrides and direction included, and moves when a letter shows (its window midpoint). A segment schedule must start at its Action's start, so text already partly typed at a cut is a static prefix plus a typed remainder. With `endBehavior:"vanish"` the caret stays solid for one `blinkRateMs` (at least a frame) after the last letter shows, then disappears, so a caret handed to a text that starts typing then overlaps it that long. A caret paints only while its text does, at the text's opacity.
- **One cascade, one Action.** A word or letter cascade is a single Action that targets `{kind:"textSegmentGroup", objectId, selector:{kind:"activeSegments"}}` and carries a `segmentSchedule`. Never author one Action per word or letter (`{kind:"textSegment", …}` per segment): it multiplies timeline rows a designer must retime one by one, breaks when the copy changes, and cannot be reshaped with `updateMotionSegmentSchedule`. Irregular timing belongs in `segmentSchedule.manualOverrides`. An Action's segment group selects the active segments only (`selector` may be left out); the `role` and `manualSegments` selectors address segments from an Expression-form block (`addMotionBlock`). Target a single `textSegment` only for a deliberate one-off accent on one word.
- A segment-scheduled Action's `durationFrames` is the envelope its schedule derives: `(count - 1) * delayFrames + templateDurationFrames` for a uniform forward or reverse stagger, longer with humanize. Leave it out of `materializeActionFacets` and `updateMotionSegmentSchedule`, with `unit` and `baseOffsetFrames`: the stage derives them from the Text and `timing.startFrame`, and refuses a sent value that differs, naming the derived one. `humanize` and `manualOverrides` left out are none on a create and keep their current values on an `updateMotionSegmentSchedule`. `updateMotionBlockTiming` names the expected values when its timing disagrees.
- `addMorph {sceneId,objectId,blockId,to,timing,easing?,hints?}` interpolates outline vertices; it does not blend shapes like metaballs. With `to:{kind:"object",sourceObjectId}`, the donor must be visible at `captureFrame` (default: the block start), and its outline is copied when the morph is added, so the donor can be removed in the same batch. `to:{kind:"network"}` supplies the target outline directly. A round target needs curved segments: the ellipse primitive has them, while polygon and star targets and an `addPath` outline have straight edges and morph angularly. Read the stage's `morphReport`, one entry per Morph with its pairs in order. When a warning (`morph_ambiguous_start`, `morph_self_intersection_risk`) flags a pair, render the Morph's midpoint; only if it twists, copy the warning's `runnerUp` into `hints.startVertex` at that pair's index, and `runnerUpReverse` into `hints.reverse` (`setMorphCorrespondence` re-pairs a Morph already added). Corner radius does not animate while a Morph owns the outline (`morph_radius_frozen`): animate it before or after the Morph's range.
- Draw-on is `addDrawErase` with `timing.startFrame` and key-editable keys; `addPath.drawOn` always starts at frame 0. Its `range` sets the stretch of the trails it works on, and its two keys sit on the range's ends. Move an endpoint with `updateMotionKey` to begin a Draw already partly drawn or to stop an Erase before the stroke is gone: every key stays within [range start, 1], a Draw's keys never fall and an Erase's never rise. On a Path with one stroke trail, `trailIds` (`addDrawErase`) and `strokeTrailId` (`addFollowPath`) may be left out; with several, the refusal lists them. Both derive their primitive and key ids from `ids.motionBlockId` when absent (`<id>:trim` or `<id>:follow`, `<id>:from`, `<id>:to`, as a Path's own draw-on names them), and Follow Path offsets left out are 0. `stroke` (colour, width) and `cornerRadius` are animatable catalog Actions.
- Gradient domains with `space:"ownerBounds"` use normalized coordinates; `width:1,height:1` spans the owner. A circular radial gradient's radius is half the box diagonal (offset 1 reaches the corners); `radialShape:"ellipse"` is CSS farthest-corner: the ellipse passes through the box corners (radii width/√2 and height/√2), so shrink the domain to fit a shape inside the box.
- A raw vector network (`addObject`, `replaceVectorNetwork`) needs `base.width/height` equal to its tight bounds within a few ulps, which fails at large absolute coordinates; rebase geometry to the origin first. `addPath` derives its bounds itself and accepts parent-local and off-canvas geometry.
- `style.objectFit:"contain"|"cover"|"fill"` applies to images and videos.
- An audio clip may not play past its source media unless it loops, and there is no silence padding: shorten the clip or anchor it later. Native AAC exports trim the encoder's priming with an MP4 edit list; a Chrome 154 export measured 0 samples of offset against the source. When sync matters, compare the exported audio with the source instead of applying a global offset.
- `{kind:"timingStyle"}` segments evaluate with their style's curve.
- A shape's or Frame's stroke sits inside its box; a network Path's stroke, and an open contour of a custom shape, is centred on its line. A Path traced along a shape's edge (to draw that edge on, say) sits half a stroke width further out than the shape's own stroke; inset it by half the width to match.
- `addFollowPath` makes two progress keys, and Studio's Follow Path inspector edits those two (from and to). A middle progress key added with `insertMotionKey` is valid, but a person can only move it in time, not change its value.
- A `color` Action on a gradient fill keeps the gradient. With two or more keys, each stop starts from its own colour and moves through the later keys (the first key's value is not painted); one with stage `in` runs the other way and lands each stop on its own colour (the last key's value is not painted). A one-key `color` Action paints its solid colour over the gradient, and keeps it after the Action ends when it holds. Stop positions and the angle do not move. On text segments, a `color` Action paints solid colours.
- A scale of exactly 0 paints nothing, and on such a frame the object's Effects are dropped (`renderFrame` warns), a Path with painted regions can fail to paint, and Studio cannot edit Scale there; a Follow Path chain refuses it outright. End a shrink at a small non-zero value, or end the lifetime there instead.
- Under a projective camera, depth orders siblings only: a child always paints over its parent (text in a filled Frame stays on top). Siblings that all lie flat in their parent's plane sort by plane depth, co-planar ones keeping layer order; otherwise the whole set sorts by centre depth. Whole objects sort, with no per-pixel depth, so two objects that intersect in depth cannot cut through each other.
- Adaptive motion blur (no `samples`) takes about one sample per project px of the box's sweep (half a px at `setMotionBlurQuality` `high`), from 3 to 31, so a faster sweep spaces its samples out and can step; `renderFrame` then warns `motion_blur_quality_limited`. A fixed `samples` runs from 2 to 32. Studio's playback and scrubbing draw at most 7 adaptive samples (a paused frame, `renderFrame` and the export draw the full count), so a fast blur can look stepped while it plays in Studio and smooth in the export.
